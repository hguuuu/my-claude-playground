## What

Implemented the first Slice-1 component: Julian Day arithmetic in `formal/core/calendar/`.

- `julian_day.py` — (Y,M,D,h,m,s UT) ↔ JD (float); integer JDN; inverses; `day_of_week(jdn)`; helpers (`is_leap_year`, `days_in_month`, `validate_date`).
- Calendar handling: `CAL_MIXED` default (Julian ≤ 1582-10-04, Gregorian ≥ 1582-10-15, the 10-day gap raises), plus proleptic `CAL_GREGORIAN` and `CAL_JULIAN` flags. Astronomical year numbering (year 0 = 1 BCE); negative years/JDN supported.
- `julian_day.md` spec note: guarantees, conventions, algorithm source.
- Tests: `formal/tests/test_julian_day.py` (unittest-style, pytest-compatible) — **23 tests / 1718 subtests, all green** via `bash formal/tests/run_tests.sh` and via `python3 -m unittest`.

J2000.0=2451545.0, JD 0, Sputnik; MJD epoch and Unix epoch as independent second sources; Gregorian-reform boundary pair). All rows marked `verified-against-source: pending-audit`.
- INDEX.md updates: `formal/core/`, `formal/tests/`, `formal/tests/fixtures/`.

## Why (decisions)

- **Algorithm source ≠ fixture source, deliberately.** Conversions use the ESAA ch. 15 / Fliegel–Van Flandern floor-division form (exact for all years); known-answer values come from Meeus ch. 7 + USNO/POSIX epochs — giving genuine cross-validation rather than testing a formula against itself (§1.3).
- **Uncertain reference values excluded rather than guessed.** The Meeus negative-year table rows failed an internal consistency cross-check from memory and were omitted, noted in the fixtures file for a future `audit:` session. Fewer certain fixtures beat many uncertain ones — the anti-fabrication rule (§1.2) applied to numbers, not just quotes.
- `datetime_from_jd` documents second-recovery precision of 1e-4 s (double-precision JD resolution near the modern era).
